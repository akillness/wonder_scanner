## 4. 결함 · 개선 제안 (파일:행 + 한 변수 수정)

1. **[중] 이름 없는 장소가 동/도로명으로 표시** — `src/geo/nominatim.js:49` `const name = String(p?.name || String(p?.display_name || '').split(',')[0] || '')`. `name`이 빈 공원(다동, 소공동, 신문로1가)이 `display_name` 첫 토큰(행정동)으로 카드에 오름. 수정: `display_name` 폴백 제거 → `const name = String(p?.name || '').trim(); if (!name) continue;` (`parseOverpass`와 동일 규칙).
2. **[하] 카메라 폴백 상태에서 빈 스냅 저장** — `src/ui/screens/scan.js:98` `doSnap`. `S.source===video`이고 `video.readyState<2`(스트림 없음)여도 라벨만 있으면 640×640 빈 JPEG가 앨범에 저장됨(I-3, 4→5). 수정: `if (S.source === video && !cameraAlive()) return setLupe('카메라가 열려야 스냅할 수 있어.');` 한 줄 가드 (`cameraAlive`는 이미 import).
3. **[하] 깜빡임/상실 유예가 `open` 필드 유무에 의존** — `src/scanner/eye.js:32` 조건 `(!sample || sample.present || sample.open < P.openMin)`. `{present:false}`(open 없음)는 300ms 유예 없이 즉시 감쇠(E-2: 24ms). gaze.js는 `open:0`을 내보내므로 현재 제품 경로는 정상(E-1)이나 어댑터 변경에 취약. 수정: `sample.open < P.openMin` → `(sample.open ?? 0) < P.openMin`.
4. **[설계 확인] 유예된 단속운동이 등급을 깎음** — `src/scanner/eye.js:42` jitter EMA가 박스 밖 샘플도 누적. 126ms 이탈(D)로 jitter 41 → GOOD, 홀드는 보존되지만 PERFECT 불가(§1 D). 의도라면 유지; 아니면 `if (!offSince) jitter += …` 로 이탈 유예 중 EMA 갱신을 건너뛰기.
5. **[디버그 훅] `injectGaze`가 `settings.eyeGauge`·`eyeWanted()`를 우회** — `src/ui/screens/scan.js:208` `const active = gazeInject !== undefined || (!!gaze && eyeWanted())`. OFF 상태 검증이 훅으로 불가(F). 수정: `const active = state.settings.eyeGauge !== false && (gazeInject !== undefined || (!!gaze && eyeWanted()))`.
6. **[디버그 훅] `syncEye`(진입 +1.2s, scan.js:79)의 `eye.reset()`이 주입 중인 홀드를 0으로 리셋** — 카메라 없음/후면(`facing='environment'`, camera.js:2)이면 항상 실행되어 진입 1.2s 이내 시작한 홀드의 fill이 .61–.87에서 0으로 떨어짐(재획득은 즉시). 제품 경로 영향 없음(전면 전환 시 리셋은 의도). 수정: `if (!eyeWanted()) { … if (gazeInject === undefined) eye.reset(); … }`.
7. **[디버그 훅] 스트림 없는 비디오에서 `injectDetection` bbox가 화면 밖으로 매핑** — `src/ar/overlay.js:29` `coverTransform`이 `videoWidth 0 → 1×1` 소스로 계산(s=844, ox=−227). QA는 `video.width/height` 지정 필요. 제안: `injectDetection`에서 `video.width ||= overlay.clientWidth; video.height ||= overlay.clientHeight;`.
8. **[사소] `eye.stats().blinks`는 유예 "프레임" 수** — `src/scanner/eye.js:32` `blinks++`가 프레임마다 증가(C: 깜빡임 1회에 7). 주석 「깜빡임 유예 횟수」와 불일치. 수정: `if (!wasBlink) blinks++` 식의 이벤트 카운트 또는 주석을 「유예 프레임 수」로.

## 5. 헤드리스 관측 (결함 아님, 기기 확인 권장)

- `settings.recordClips=true`(기본)일 때 공명 0.6에서 `recorder.start`(캔버스 captureStream + AudioContext 오디오 트랙, `src/scanner/recorder.js:22-28`) 직후 rAF가 **2.9–3.1s 정지**하고, 튜토리얼 실제 클릭(사용자 활성화)으로도 재현. 이후 다음 스캔 진입이 30s 이상 멈춤. `sound=false`이면 정상(홀드 936ms). 헤드리스 MediaRecorder 특성으로 보이며 폰에서 클립 녹화 시 히치 여부만 확인 요망.
- 카메라가 없어도 `#eyeHud`는 「전면 카메라에서 시선 추적이 켜져요」로 정확히 안내(모델 로드 없음). 단 디버그 `calibrate()`는 조건과 무관하게 「시선 ON」으로 덮어씀(scan.js:83, 디버그 전용).
